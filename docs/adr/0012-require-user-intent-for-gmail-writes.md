# Require active user intent for Gmail writes

Zmail performs Gmail mutations only from explicit actions in the active web UI, with one deliberate extension: opening an unread Message authorizes mark-read only after the configured Read dwell time elapses while that Message remains selected and the page remains visible and focused. Losing any condition cancels the timer, all IMAP body reads use non-mutating peek semantics, and background refresh, prefetch, Search, API reads, and passive navigation never write to Gmail. Read dwell time defaults to three seconds, accepts 1 through 60 seconds, and uses zero to disable automatic mark-read rather than make it immediate. Apart from that continuation of the Message-opening action, an idle UI is quiescent: it initiates no polling, prefetch, automatic retry, IMAP IDLE work, or other Gmail reads or writes until the App user acts, though a previously authorized Interaction lease may remain open briefly without application-level IMAP commands. Failed reads stop with an explicit Manual retry affordance, and failed Mailbox actions are never repeated automatically because their remote outcome may be uncertain. Mailbox actions express idempotent target states so an App user can safely repeat the same action after an uncertain response. The UI waits for Gmail success before applying an action to browser memory and does not optimistically update or automatically re-read Gmail afterward.
